# 设备档案导入导出

## 功能概述

设备管理 → 设备档案模块（`/device/archive`）提供设备档案的增删改查及 Excel 导入导出：

- **导入模板**：包含「设备编号、设备名称、设备类型、部门、位置、责任人」六列，前两列为必填。
- **两步导入**：上传后先校验（必填项 + 编号查重），展示通过/失败行数，用户点击「确认入库」后数据才落库；失败行不入库。
- **失败行下载**：校验后可下载 xlsx，文件在原始六列基础上增加「行号」「失败原因」列，便于修正后重新上传。
- **按条件导出**：列表勾选了行时导出选中行；未勾选时携带当前搜索表单的全部条件导出设备档案。

## 交互流程

```
下载模板 → 填写上传 → 服务端解析校验（暂存30分钟）
                 ├─ 全部通过 → 确认入库
                 ├─ 部分失败 → 下载失败行查看原因 → 修改后重新上传 / 仅确认入库通过行
                 └─ 全部失败 → 修改文件后重新上传
```

校验规则：

1. 设备编号、设备名称必填，为空记为失败行。
2. 设备编号与库中已有数据重复，记为失败行。
3. 设备编号在同一文件内重复，第二行起记为失败行。
4. 整行空白自动跳过，不计入行数。
5. 确认入库时会再次查重，防止校验后并发新增导致重复编号。

## 后端接口

基础路径：`/device/archive`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/list` | 分页查询（设备名称模糊匹配，其余条件精确） |
| POST | `/add` | 新增（编号唯一校验） |
| PUT/POST | `/edit` | 编辑（编号唯一校验） |
| DELETE | `/delete`、`/deleteBatch` | 删除/批量删除 |
| GET | `/queryById` | 详情 |
| GET | `/importTemplate` | 下载导入模板（xlsx，含填写规则标题行） |
| POST | `/importCheck` | 上传并校验，返回 `sessionId` 与通过/失败统计（不入库） |
| POST | `/importConfirm?sessionId=` | 确认入库暂存的有效数据 |
| GET | `/importError?sessionId=` | 下载失败行 xlsx（含失败原因） |
| GET/POST | `/exportXls` | 按当前搜索条件导出（支持 `selections` 选中行） |

代码位置：`org.jeecg.modules.device.archive`（jeecg-module-demo）

- `entity/DeviceArchive`：档案实体（继承 JeecgEntity，审计字段自动填充）
- `vo/DeviceArchiveImportVo`：导入模型，与模板列一一对应
- `vo/DeviceImportErrorVo`：失败行模型（行号 + 原始列 + 失败原因）
- `util/DeviceImportCache`：暂存会话内存缓存，30 分钟过期、按登录人隔离；集群部署可替换为 Redis
- `service/impl/DeviceArchiveServiceImpl#importCheck/confirmImport`：校验与入库逻辑

## 前端页面

- `src/views/device/archive/index.vue`：列表页（查询、新增、导入、导出、批量删除）
- `DeviceImportModal.vue`：两步导入弹窗（模板下载、上传校验、结果预览、失败行下载、确认入库）
- `DeviceModal.vue`：新增/编辑弹窗
